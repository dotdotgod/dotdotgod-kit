# 역할 목록

한국어 역할 정의 초안. 아래 17개 역할은 위임할 때 읽고 전달하는 책임 지침이며, 자동으로 등록되는 에이전트 설정이 아니다.

## 요구사항과 기준

- [사용자 요구사항 담당](user-requirements.md): 사용자 관점의 요구사항과 우선순위를 확정한다.
- [데이터 요구사항 담당](data-requirements.md): 사용자 요구를 충족하는 데 필요한 데이터 조건을 확정한다.
- [검증 필수사항 확정 담당](validation-requirements.md): 필수 Validation을 정하고, 저장·조회·상태·동시성에서 지켜야 할 조건을 확정한다. 별도의 구현 검토 담당은 두지 않는다.

## 설계

- [전체 설계 지휘자](design-conductor.md): 확정된 요구와 기준을 각 설계에 전달하고 설계를 통합한다.
- [UX 설계 담당](ux-designer.md): 사용자 흐름과 상호작용을 기술 설계보다 먼저 구체화한다.
- [Presentation Layer 설계 담당](presentation-layer-designer.md): 확정된 UX를 화면·컴포넌트·인터랙션으로 설계한다. 화면 설계에는 반드시 ASCII 아트를 포함한다.
- [Data Network Layer 설계 담당](data-network-layer-designer.md): 저장 구조와 외부 통신 계약을 확정한다.
- [테스트 설계 담당](test-designer.md): 구현 전에 무엇을 어떤 조건으로 검증할지 확정한다.

## 리뷰

- [보안 설계 리뷰어](security-reviewer.md): 각 설계의 신뢰 경계·권한·정보 노출과 보안 검증 누락을 검토한다. 별도 보안 설계 담당은 두지 않는다.

- [UX 설계 리뷰어](ux-reviewer.md): 사용자 흐름이 요구사항과 맞는지 검토한다. 불필요한 단계·선택·확인과 필수 오류·복구 흐름의 누락을 찾는다.
- [Presentation Layer 설계 리뷰어](presentation-layer-reviewer.md): ASCII 아트가 UX와 맞는지 검토한다. 과도한 컴포넌트·상태·추상화, 중복 Validation, 불필요한 폴백을 찾는다.
- [Data Network Layer 설계 리뷰어](data-network-layer-reviewer.md): 스키마·요청·응답·통신 계약이 서로 일치하는지 검토한다. 테이블·필드·계층·락이 불필요한지, 삭제·재시도 정책에 근거가 있는지 확인한다.
- [테스트 설계 리뷰어](test-reviewer.md): 요구사항과 필수 검증의 누락, 같은 보장을 반복하는 테스트를 찾는다. 테스트가 구현 세부사항에 과도하게 결합되어 있는지, 기대 결과가 타당한지 검토한다.
- [전체 리뷰 지휘자](review-conductor.md): 영역별 리뷰를 통합한다. 전체 설계의 충돌·누락·중복과 리뷰 의견 사이의 충돌을 검토하고, 수정 요청을 전체 설계 지휘자에게 전달한다.

## 태스크 계획

- [작업 계획자](task-planner.md): 사용자와 확정한 설계를 실행 가능한 페이즈와 태스크로 나누고 의존관계·병렬 그룹·실행 순서를 정한다. 구현 세션에 구현 담당 역할을 전달한다.

## 구현 인계

- [최소하지만 완결된 구현 담당](implementer.md): 명시적으로 구현을 맡은 세션이 사용하는 역할. 기능·테스트를 함께 완결하고 근거 없는 검증·DB 락·폴백·제약을 추가하지 않는다. 계획 단계에서는 실행하지 않는다.

## 최종 보고

- [최종 완료 보고서 작성 담당](completion-reporter.md): 계획 작성·구현 배치·전체 작업을 구분하여 실제 산출물과 검증 결과를 보고한다. 비가역 실행의 선택 이유·근거·대안·승인 조건과 미검증 위험을 기록하며, 보고 자체를 구현 수행이나 실행 승인으로 취급하지 않는다.

## 공통 규칙

역할을 배정하거나 수행하기 전에 [역할 공통 규칙](../references/COMMON.md)을 읽는다.
