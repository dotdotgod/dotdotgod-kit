# Plan Generator Smoke Tests

1. Run `/plan-generator --help` and confirm usage is shown without creating `docs/plan/` files or sending a Stage 01 authoring prompt.
2. Run `/plan-generator` with no args and confirm the first-request editor opens when custom UI is available; without a request, confirm no follow-up is sent.
3. Run `/plan-generator add staged authoring smoke` and confirm the UI first shows startup progress such as `generating plan slug`, then creates an LLM-proposed kebab-case path, or a deterministic request-derived fallback such as `docs/plan/add-staged-authoring-smoke/README.md` when no model proposal is available; confirm it creates `.dotdotgod-plan/01_INTAKE.md` through `dotdotgod plan stage create`, stores `currentStage: 01-intake`, marks status `active`, and immediately sends the Stage 01 authoring prompt with a bounded `Current stage checkpoint context` block for `.dotdotgod-plan/01_INTAKE.md`.
4. On the next `agent_end`, confirm Stage 01 authoring is not sent a second time and Plan Mode does not open its execute/stay/refine/cancel review while `/plan-generator` is active.
5. Run `/plan-generator --stop` and confirm the generator stops, clears the shared workflow flag, and Plan Mode can resume normal execution review behavior. During an active generator run, press Esc/app interrupt or run no-arg `/plan-generator` and confirm the generator records `status: input-waiting`, preserves `currentPlan/currentStage`, keeps workflow suppression active, and resumes the same stage from the next user message.
6. Run `/plan-generator docs/plan/<task>` and confirm non-README path-like input is treated as a new request. Then run `/plan-generator docs/plan/<task>/README.md`: missing README paths should warn without creating a slug, existing README paths with no checkpoint should create `01_INTAKE.md` and queue Stage 01 in place, existing paths with a checkpoint should resume that stage with bounded checkpoint context, and completed final checkpoints should not queue another stage.
7. Complete Stage 01 intake with request summary, goal, likely targets, unknowns/risks, and next-stage context; confirm `agent_end` creates `.dotdotgod-plan/02_CONTEXT_LOAD.md` through `dotdotgod plan stage create`, advances to `02-context-load`, and sends one handoff with bounded `Next stage checkpoint context` content that treats `.dotdotgod-plan/**` as internal stage state context.
8. Complete Stage 02 context-load by updating the durable plan artifact with `Memory Reads`, `Impact Candidates`, `Related Files`, and `Stage 02 Construction Checklist`; if `.dotdotgod-plan/02_CONTEXT_LOAD.md` exists, confirm it has `Stage: 02-context-load`, valid `Status:`, and `Updated:` metadata.
9. Continue Stage 03 through Stage 05 and confirm each pass creates the next `.dotdotgod-plan/NN_STAGE_NAME.md` checkpoint before advancing. Stage 04 should produce handoff-ready implementation design with code touchpoints, data/state flow, edge cases, tests, and atomic completion criteria; the checkpoint evaluation should retry if Atomic Tasks or Edge Cases are too generic for another agent to implement without guessing. When the design spans multiple implementation parts, confirm the plan is split into task-local support markdown files and `README.md` links them. Stage 05 pass should clear or complete the current stage without sending another handoff. For small plans, Stage 05 may state that no split workstream handoff is needed.
10. Force retry and malformed evaluation results after bootstrap and confirm `sendUserMessage` is emitted from `agent_end` with bounded current checkpoint context, store status remains `active`, the breaker increments, `currentStage` is preserved, and the breaker cap stops as blocked after 5 loops.
11. Force a user-input blocked result and confirm the store records `status: input-waiting`, preserves `currentPlan/currentStage`, keeps `/plan-generator` workflow suppression active, and does not queue a follow-up until the user provides more input. Then send relevant follow-up input and confirm the same stage resumes with bounded current checkpoint context. Confirm `/plan-generator --stop`, completed workflows, and retry-exhausted blocked states do not auto-resume.
12. Re-run the Plan Mode boundary checks: `/plan <request>` must not auto-run `/plan-generator`, and Plan Mode must not write `.dotdotgod-plan` stage state context files.
