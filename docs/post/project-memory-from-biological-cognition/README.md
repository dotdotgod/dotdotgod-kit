# 닷닷갓은 작업자가 인지하고 관리하기 편한 프로젝트에서 시작되었다

AI를 효과적으로 활용하려면 AI가 사용하는 프로젝트 환경을 작업자가 먼저 이해하고 관리할 수 있어야 한다. 닷닷갓은 작업자가 필요한 기억을 쉽게 찾고, 문서와 작업 영역의 관계를 명시적으로 관리할 수 있는 프로젝트를 만드는 데서 시작했다.

인지능력과 사고능력은 모두 지적 활동에 속하지만 범위와 초점이 다르다. 인지능력은 외부 정보를 받아들이고 인식하며 기억하는 기초 과정이다. 사고능력은 우리의 욕구에 따라 인지한 정보의 중요도를 정하고, 우선순위를 부여해 배치하고 조합하는 능력이다.[^thinking] 인공 신경망은 인간의 사고를 그대로 재현하기보다 자연계의 신경망에서 나타나는 인지 기능을 모방하는 형태로 발전해 왔다. 생명체가 환경의 신호를 받아들이고, 특징을 구분하고, 경험에서 패턴을 학습해 다음 반응을 조정하는 방식이 그 출발점이다.[^cognition]

인지 기능은 주어진 신호에서 차이와 관계를 찾아 패턴으로 구성한다. AI가 프로젝트를 인식할 때는 이름, 경로, 문서의 역할과 링크가 이 판단을 돕는 인지 단서가 된다. 사람이 이해하고 관리할 수 있도록 정보의 역할과 관계를 명시하면, AI도 그 구조를 따라 현재 작업에 필요한 단서를 더 안정적으로 찾을 수 있다.

**사람이 잘 인식할 수 있는 프로젝트가 AI의 인지 능력도 잘 활용할 수 있는 프로젝트다.**

이것이 닷닷갓의 출발점이다.

## 기억은 목표와 사건에서 시작된다

우리는 미래의 목표에 따라 필요한 것을 떠올린다. 앞으로 만들 결과를 생각하며 규칙과 요구사항을 찾고, 필요한 지식과 과거 경험을 불러온다. 작업을 시작할 때 프로젝트 메모리부터 찾는 이유다.

동시에 우리는 이미 일어난 일이나 지금 마주한 것에서도 필요한 기억을 떠올린다. 작업을 마친 뒤 실제로 변경된 파일을 보면 그 결과가 영향을 줄 수 있는 범위와 함께 확인할 항목을 생각한다. 목표에서 기억으로 향하는 탐색과 사건에서 기억으로 돌아오는 탐색이 함께 일어난다.

닷닷갓은 이 두 기억의 방향을 서로 다른 탐색 경로로 구현한다. 벡터 검색은 질문이나 목표에서 의미가 가까운 문서를 찾고, 그래프는 문서와 소스 사이에 형성된 관계를 표현한다. 두 방식은 이미 널리 사용되고 있으며 닷닷갓도 프로젝트 메모리의 탐색 경로로 활용한다. `impact`는 변경 파일을 시작점으로 삼아 실제 작업 결과에서 검토 범위를 역으로 계산한다.

```text
작업 시작: 목표와 요청 → 필요한 프로젝트 메모리
작업 완료: 변경된 파일 → 영향을 받는 문서·테스트·소스
```

## 프로젝트에 사이코메트리 능력을 주고 싶었다

인지하기 좋은 구조는 필요한 기억을 찾는 데서 끝나지 않는다. 이미 일어난 변경에서 관련 기억을 다시 불러올 수 있어야 한다. 닷닷갓은 이 역방향 인지를 프로젝트의 **사이코메트리 능력**으로 보았다.

사이코메트리가 손에 닿은 물건에 남은 흔적에서 관련된 기억을 읽어내는 능력이라면, `impact`는 변경된 파일에서 출발해 그 파일과 함께 검토해야 할 프로젝트 기억을 불러내는 능력이다. 하나의 파일을 변경했을 때 다시 읽어야 할 스펙, 확인해야 할 아키텍처 제약, 실행해야 할 테스트와 검증 명령의 범위를 프로젝트의 흔적에서 측정한다.

```bash
dotdotgod graph impact . --changed <changed-file>
```

이 명령은 변경된 파일을 하나의 사건으로 받아들이고, 그 사건에서 관련 문서, 테스트와 소스로 기억을 거슬러 올라간다.

## 트레이서빌리티가 파일에 기억을 남긴다

사이코메트리가 흔적을 읽으려면 먼저 흔적이 남아 있어야 한다. 닷닷갓에서는 사람이 읽고 수정할 수 있는 문서를 프로젝트 기억의 원본으로 두고, 문서와 해당 문서를 기준으로 작업한 영역을 명시적으로 연결한다.

이 연결이 트레이서빌리티다. 어떤 스펙이 어느 소스에 구현되었는지, 어떤 테스트로 검증되는지, 어떤 관련 문서와 검증 명령을 함께 확인해야 하는지를 관리한다. README 목차와 문서 링크, 프로젝트 구조도 관계를 찾는 단서가 된다.

트레이서빌리티는 문서에서 작업 영역으로 향하는 길을 만들고, `impact`는 그 길을 반대로 따라간다. 변경된 파일을 손에 쥐고 그 파일에 연결된 스펙, 아키텍처, 테스트와 검증 기억을 불러오는 것이다.

검색 결과와 그래프는 이 원문과 관계를 탐색하기 위한 경로다. 사람이 문서와 작업 영역의 연결을 고치면 `impact`가 찾아가는 검토 범위도 함께 달라진다. 프로젝트가 작업의 흔적을 명시적으로 기억할수록 변경 파일에서 더 구체적인 관련 기억을 복원할 수 있다.

## 변경에서 기억으로 돌아오는 경로

작업자가 프로젝트를 쉽게 인지하고 관리할 수 있게 만드는 것이 닷닷갓의 출발점이다. 프로젝트의 이름, 경로, 문서 역할과 관계를 명시하면 사람은 필요한 기억을 찾을 수 있고 AI도 같은 구조를 인지 단서로 활용할 수 있다. `impact`는 이 단서를 작업이 끝난 자리에서 다시 읽어내는 구현이다.

작업을 시작할 때는 목표에서 필요한 문서로 향하고, 작업을 마칠 때는 변경된 파일에서 관련 기억으로 돌아온다. 두 경로가 연결되어야 스펙, 구현과 테스트가 같은 프로젝트 상태를 설명할 수 있다.

[^thinking]: 내 생각에는 사고능력의 핵심은 `우리`라는 주체와 그 주체가 느끼는 `욕구`다. 인지한 정보의 중요도와 조합을 결정하는 기준이 주체의 위치와 욕구에서 나오기 때문이다. 이 글은 사고능력의 대체 가능성보다 AI가 활용하는 인지 단서를 어떻게 관리할지에 집중한다.

[^cognition]: 이 글에서 인지 기능은 특정 신호에서 패턴을 찾는 기능을 넓게 뜻한다. AI는 자연계의 인지 기능을 모방하는 데서 출발했지만 거기에 한정되지 않는다. 생물에게 존재하지 않는 종류의 신호를 포함해, 우리가 신호로 정의할 수 있는 모든 대상에서 패턴을 찾는 방향으로 새로운 인지 기능을 만들고 확장하고 있다.
